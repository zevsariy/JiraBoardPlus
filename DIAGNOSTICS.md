# Диагностика Jira

Раздел предназначен для инженеров, у которых есть обычная сессия Jira в браузере. Доступ к мониторингу сервера не требуется. Откройте **Board Plus → Диагностика Jira**, выберите вкладку настроенного подключения.

1. Начните пассивную запись на 30–300 секунд. Перейдите в Jira и воспроизведите проблему. Запись не создаёт запросов; доступный старый буфер ресурсов можно включить отдельно.
2. Вернитесь в диагностику и отметьте наблюдаемый сбой. Метка использует текущее время UTC, поэтому ставьте её как можно ближе к событию. Остановите запись или дождитесь лимита.
3. При необходимости откройте «Сеть и HTTP» и запустите 3–10 проб serverInfo либо myself. Это реальные запросы с текущей сессией, отдельные от пассивного наблюдения.
4. Изучите выводы, разбивку фаз, медленные группы запросов, Server-Timing и браузерные задержки. Каждый вывод содержит наблюдение, интерпретацию и следующий шаг проверки.
5. Сохраните снимок или скачайте JSON/Markdown. Для администратора можно отдельно включить адрес Jira и request/node ID. JSON содержит подробные измерения; Markdown — краткую сводку.

## Показатели и границы интерпретации

| Область | Что измеряется | Как интерпретировать |
| --- | --- | --- |
| Сеть | DNS, TCP отдельно от TLS, ожидание до отправки, TTFB, получение тела, P50/P95/max/N | Только фазы, раскрытые Resource Timing. Нулевое подключение может означать повторное использование; неизвестное не заменяется нулём. |
| HTTP-пробы | Полное время, время до заголовков, результаты и нестабильность серии | Сквозная HTTP-задержка, не ICMP RTT и не потери пакетов. В фоне таймеры и обработчики могут задерживаться. |
| Сервер и прокси | HTTP 429/5xx, Server-Timing, версия/сборка, request/node ID, Date | TTFB включает сеть, прокси, очереди и обработку. Server-Timing доступен только если сервер его отдаёт; метрики могут перекрываться, имена определяет сервер. |
| Браузер | Long tasks ≥50 мс, задержка таймера в видимой вкладке, JS errors/rejections, загрузка документа, FCP/LCP, сумма layout shifts, DOM count | Long task не является процентом CPU. Сумма shifts за запись не является стандартным оконным CLS. Счётчики ошибок не заменяют Console/Performance trace. |
| Память и соединение | Необязательная JS heap estimate, Network Information | Heap — неточная оценка Chromium, не вся память вкладки. RTT/downlink Network Information относятся к общей оценке браузера, не к корпоративной Jira. |
| Расширение | Общий бюджет запросов, ошибки, ожидания, активные слоты | Счётчики Board Plus с начала сессии браузера, не весь трафик Jira и не TCP-сокеты. |

**CPU/RAM сервера, JVM heap/GC, Tomcat threads, пул и запросы БД, индексация, кластер, диски и внутренние очереди недоступны через обычную страницу Jira.** Для них администратору понадобятся логи или серверный мониторинг за интервал отчёта. Расширение не подставляет оценки вместо этих данных.

Вкладка со сбоями должна быть видимой во время воспроизведения. Задержка таймеров в фоне не включается в оценку зависания интерфейса. Перезагрузка или переход на другой документ завершает старую запись: экран сохраняет последний считанный снимок, для нового документа нужна новая запись. Если закрыть экран диагностики, пассивный сбор в Jira остановится по своему лимиту (не позднее 5 минут); текущая активная проба ограничена тайм-аутом, следующая не запускается.

Resource Timing может не показать все ранние ресурсы: браузерный буфер ограничен. Cross-origin фазы скрываются без Timing-Allow-Origin. HTTP status поддерживается не всеми версиями браузера; 0/отсутствие означает неизвестное. Группы маршрутов обезличены. Данные Performance API доступны скриптам страницы и не являются независимым защищённым источником аудита.

## Ограничения нагрузки и хранения

- Пассивно: не более 2000 ресурсов, 500 long tasks, 1000 измерений задержки таймера и 100 отметок; вытеснение старых записей отражается в отчёте. DOM count считывается не чаще раза в 10 секунд.
- Активно: один GET одновременно, минимум 2 секунды между стартами, общий бюджет Board Plus, 15 секунд на запрос и до 256 КиБ тела. Ожидание бюджета не включается в измеренную задержку. Серия ограничена 5 минутами вместе с ожиданием.
- HTTP-ошибка, ответ не JSON или два подряд сетевых сбоя останавливают серию. 429/5xx дополнительно включают паузу общего бюджета. Никаких обходов ограничений сервера.
- Буфер активных результатов — до 100 последних проб. До пяти сохранённых отчётов для каждой Jira; сохранение и удаление выполняются вручную. Открытие и сравнение снимков не обращается к сети.
- В экспорт не включаются названия вкладок, URL-параметры, ключи задач, тела, cookies, авторизационные заголовки, тексты Console или ошибок. Имена Server-Timing остаются как заданные сервером, описания исключаются.

Для сравнения повторяйте одинаковый сценарий с одинаковой длительностью и составом запросов. Указываются размер выборки и P95; для трёх проб P95 фактически близок к максимуму и не описывает долговременный SLO. Различия до/после отключения функций расширения сами по себе не доказывают причинность.
