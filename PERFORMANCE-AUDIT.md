# Аудит производительности — 2026-11-28

Версия: 0.32.0 → 0.32.1. Проверены обработка доски (active-board/content), аналитика Control и подготовка роадмэпа. Корпоративная Jira не использовалась: все данные синтетические.

## Исправленные узкие места

- `src/control-core.js`: одна история задачи разбиралась и сортировалась повторно для строк, когорт и итогов спринта. Теперь результат переиспользуется в пределах одного вызова analyze. После изменения снимка следующий вызов считает заново; постоянного кэша нет.
- Подсчёт возвратов создавал срез истории для каждого перехода и искал в нём предыдущий статус (квадратичный рост). Теперь используется множество предыдущих статусов и один проход. Текущий переход добавляется после проверки, чтобы не изменить смысл самопереходов.
- Каждый процентиль просматривал всю когорту и создавал промежуточный массив. Теперь когорты сортируются один раз, число длительностей ≤ возраста определяется бинарным поиском. Повторы, минимальный размер когорты и неизвестные значения сохранены.
- `src/roadmap-core.js`: при добавлении каждой задачи и зависимости сериализовался весь растущий JSON. Теперь сериализуется только новая строка, учитываются разделители и изменение длины счётчика пропущенных задач. Порядок, ограничения 145000/185000 и итоговый объект сохранены.

## Остальные наблюдения

- REST-загрузка доски уже ограничена общей блокировкой вкладок, кэшем, паузой скрытой вкладки и Retry-After. Искусственно ускорять её увеличением количества запросов без замеров сервера не стали.
- В active-board уже есть сравнение сигнатур меток, чтобы не пересоздавать неизменившееся содержимое. Однако полные обходы видимых карточек и повторный анализ рисков при DOM-изменениях остаются кандидатами для отдельного браузерного профилирования.
- В content наблюдение за всем body и секундный опрос панели могут создавать лишнюю работу. Сужение наблюдения требует отдельной проверки переходов Jira и замены контейнеров; в этот патч не включено.
- Рекурсивный обход зависимостей роадмэпа с копированием пути может стать проблемой на очень длинных цепочках. Нужен отдельный нагрузочный сценарий графа; ускорение этого участка здесь не заявляется.
