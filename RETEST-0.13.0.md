# Ручная проверка 0.13.0 — Роадмэп релиза

Подготовка: обновите распакованное расширение на chrome://extensions. Укажите сервер и проект в настройках, войдите в Jira. Для проверки нужна fix version у Component, Epic с Parent Link на этот Component и Task с Epic Link на Epic. Реальные запросы в ходе разработки не выполнялись.

1. **Запуск и справочники.** Откройте меню расширения → «Роадмэп релиза». Ожидается новая вкладка; список релизов проекта загружается автоматически. Введите часть имени в другом регистре и выберите вариант кликом или Enter. ID вручную не нужен.
2. **Настройки иерархии.** Разверните настройки. Проверьте три уровня, поля Parent Link/Epic Link, Rank, Team, Target Start/End, Sprint. При нестандартных названиях выберите поля поиском. Несколько типов на уровне — Ctrl/Cmd + клик. Сохраните. Ожидается автоматическая загрузка выбранного релиза; настройки сохраняются после закрытия вкладки. Пустой обязательный тип/поле даёт закрываемое сообщение.
3. **Полнота и порядок.** Дайте дочерней Task другую fix version или очистите её. Обновите. Task остаётся под Epic, порядок соседей соответствует Rank. Клик по названию показывает другое/пустое значение релиза. Корневой Component другого релиза отсутствует.
4. **Сроки.** У Component Due Date раньше конца Task. Обновите. Полосы Task и родителей красные, родительский интервал доходит до конца Task, в сводке нарушение. Нажмите кнопку фичи в сводке: видны срок, превышение и просрочка. Удалите даты у листовой задачи: срок не должен стать подтверждённым. Без Due Date результат также неопределённый.
5. **Спринты.** Назначьте Task спринту с датами, смените приоритет на спринты и сохраните. Полоса соответствует спринту; под ней отдельная полоса с названием. Старые закрытые спринты не растягивают план при наличии активного/будущего. Если у выбранного источника нет полного интервала, используется другой; без обоих показывается отсутствие интервала.
6. **Team.** Назначьте потомкам разные команды. Выберите «По командам», затем одну Team. Виден её набор задач и родители с подписью «контекст». Контроль всей фичи не сужается до выбранной команды. Пустая Team доступна как «Без Team». Если сервер не отдаёт названия Shared Team, видны ID и предупреждение.
7. **Зависимости.** Добавьте две связи is blocked by, одну на внешнюю задачу. Задайте блокеру конец не раньше начала зависимой задачи. Ожидаются стрелка от блокера, красный конфликт в таблице, внешний блокер отдельной строкой. Переведите одного блокера в статус разблокировки из общих настроек: только его связь помечается разблокированной. Свёрнутые задачи остаются в таблице зависимостей. Недоступный блокер — «Недостаточно данных». Цикл отражается в качестве данных.
8. **Управление.** Поочерёдно снимите галочки стрелок, спринтов, сроков; исчезают только соответствующие элементы. Проверьте недели/месяцы, сворачивание и горизонтальную прокрутку. Клик по полосе открывает детали, ключ открывает Jira в новой вкладке. Никаких операций сохранения в Jira нет.
9. **Обновление и отмена.** Быстро смените релиз во время загрузки: итог соответствует последнему выбору. Отмена прекращает загрузку, доступна повторная. При завершившейся сессии ожидается закрываемая ошибка, не пустой «успешный» план.
10. **Экспорт.** Нажмите «Выгрузить JSON». Файл содержит релиз, иерархию, даты, Team, зависимости и предупреждения, не содержит личных заметок. Ссылки на задачи остаются доступны в интерфейсе.

Ограничения первой версии: текущие доступные задачи настроенных типов; до 2000 в иерархии, 500 внешних блокеров, 250 спринтов. Автоматического расписания и записи дат в Jira нет. Цвет нарушения — контроль Due Date фичи, не прогноз по скорости команды.
