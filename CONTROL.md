# Контроль команды — Jira Board Plus 0.27.0

Открывается из меню расширения, общей навигации или Board Plus в Jira.
Пункт внутри Jira открывает отдельную вкладку расширения.

## Первый запуск

1. Задайте JQL команды. Для анализа истории и прогноза включите завершённые
   задачи; для журнала спринта — также задачи, удалённые из спринта.
2. При необходимости загрузите каталог полей. Выберите Team, Sprint, оценку
   и поле родителя. Стандартный Parent используется без дополнительного поля.
3. Укажите завершённые статусы. Для исторического плана/факта задайте ID
   спринта и начало периода; конец по умолчанию — дата снимка.
4. Загрузка истории включается отдельно и требует одного запроса на задачу.
   Лимит — 300 задач с историей или 3000 без истории. Превышение даёт явно
   отмеченную частичную выборку, для которой прогноз недоступен.
5. Нажмите «Загрузить и сохранить снимок». Смена вкладок раздела не обращается
   к Jira. Сохранённый снимок открывается без сети и показывает дату и учётную запись.

## Правила достоверности

- Возраст и время повторного открытия — календарные дни 24×7, не рабочее
  время и не трудозатраты. Due Date сравнивается по календарной дате UTC.
- Неполная история не превращается в нулевую длительность или отсутствие возвратов.
  Запрошенная расширенная история Jira может быть обрезана сервером; в таком
  случае исторические агрегаты остаются неизвестными.
- Возраст блокирующей связи не равен непрерывному времени блокировки.
- Рост очереди — наблюдение по выбранному JQL, не доказательство причины узкого места.
- По умолчанию блокирующей считается связь с `outward = blocks`. Для других
  языков/типов задайте ID направленного типа связи; направление должно быть
  «блокирует» наружу и «блокируется» внутрь.
- Сравнение состава отражает попадание в JQL и выход из него, не создание
  и удаление задач. Снимки разных аккаунтов и JQL не сравниваются.
- План/факт ограничен загруженной выборкой. Для оценки на дату нужна полная
  история; суммы неизвестных оценок не подменяются нулём. Original Time Estimate
  хранится в секундах; Story Points не смешиваются с часами.
- Прогноз требует минимум пяти завершений, учитывает нулевые дни и предполагает
  неизменный поток. Он не моделирует новые задачи, смену команды, зависимости
  и календарь отпусков. Результаты свыше 3650 дней показываются как выход за горизонт.
- Правила на карточках используют доступные данные карточек. Новые отдельные
  запросы истории ради подсветки не запускаются. Процентиль на доске относится
  только к загруженным карточкам, в контроле — к выбранному JQL.

## Хранение и нагрузка

До 30 последних снимков, общий размер контроля до 20 МБ. Перед превышением
размера загрузка сообщает об ошибке сохранения; удалите старые данные вручную.
Очистка по возрасту относится к текущей Jira. Старые снимки сверх 30 вытесняются.
Изменения снимков сериализуются между вкладками через Web Locks.

Бюджет распространяется на Jira API расширения во всех его разделах и вкладках;
штатный JavaScript Jira и запросы модели в него не входят. Слот удерживается до
получения тела ответа. Ошибки 429/5xx включают паузу с учётом Retry-After.
Счётчики и активные слоты переживают перезапуск service worker в рамках сессии
браузера. Незавершённый слот освобождается через 30 секунд. Длительное ожидание
может завершиться обычным тайм-аутом клиента, после которого доступен ручной повтор.

Общий архив — переносимый JSON локальных данных для сохранности, без автоматического
восстановления всех модулей. Копия контроля восстанавливает снимки и отметки
refinement после просмотра; существующие ID и отметки сохраняются. Настройки и
правила из копии не заменяют текущие автоматически. Импорт ограничен текущей Jira
и 25 МБ. Полный архив включает личные заметки; отдельная копия контроля — нет.

ИИ использует существующее разрешение анализа доски. Ни один новый сценарий
не отправляет данные модели без просмотра снимка и явной кнопки отправки.
