# Проверка общих статусов · 0.7.6

1. Обновите расширение и вкладки. В меню расширения должна быть версия 0.7.6. Раскройте «Общие правила статусов». Видны два поля названий и общая галочка категории Done, отдельные ID вводить не нужно.
2. Введите реальные названия рабочих и завершённых статусов вашей Jira через запятую. Для проверки поменяйте регистр и добавьте пробелы по краям. Нажмите «Применить». Повторно откройте меню — значения сохранены, пробелы и повторы нормализованы. Уже настроенные ранее завершённые статусы не должны потеряться после обновления версии.
3. Выберите доску и спринт в «Метриках команды». В паспорте доски больше нет полей рабочих/завершённых ID; есть пояснение с общими названиями. Оценки SP/Original Time Estimate и подзадачи остаются отдельными настройками доски. В пояснении расчётов Cycle time отображаются общие названия статусов.
4. Откройте родной Sprint Report той же доски и загрузите данные расширения. Должны использоваться те же названия и галочка категории Done. Для одинакового спринта, оценок, фильтров и среза данных Cycle time и возвраты должны совпадать с дашбордом метрик.
5. Оставьте отчёты открытыми, измените общие названия в меню расширения, примените. Текущие панели перезагружают расчёты. Настроенные daily и блокировки также используют новый список завершения: Blocked становится «РАЗБЛОКИРОВАНА» только когда завершены все доступные блокеры; неизвестный статус блокера не трактуется как завершённый.
6. Попробуйте указать одно имя одновременно рабочим и завершённым, различая только регистр. Сохранение должно показать ошибку и не применить конфликт. Если конфликт возникает из-за категории Done, он обнаруживается при загрузке справочника Jira и объясняется в ошибке отчёта.
7. Укажите несуществующее название рабочего статуса. После загрузки откройте «Определения и качество данных»: видно предупреждение о не найденном названии. Если ни одного рабочего статуса не найдено, Cycle time неизвестен, вместо ложного нуля показано «—». Верните корректные настройки после проверки.
8. Сохраните снимок, затем поменяйте общие правила и откройте этот снимок. Он должен показывать исторические данные и сообщение, что использует правила на момент сохранения. Новые правила применяются при «Обновить данные», сохранённый снимок не переписывается.

JQL и категории задач родного Sprint Report определяет Jira; общие правила расширения не переписывают запросы и workflow. Время по статусам Timepiece продолжает использовать выбранные календарь и режим визитов.
