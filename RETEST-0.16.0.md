# 0.16.0 — Component/s → релиз

1. Обновите расширение и откройте роадмэп. Список Component/s должен загрузиться из проекта общих настроек. До выбора компонента поле релиза неактивно; задачи не запрашиваются.
2. Введите часть названия компонента в другом регистре, выберите кликом или Enter. Он появится отдельной меткой; можно добавить ещё несколько. Это значения стандартного поля Component/s, не задачи типа Component.
3. Выберите релиз. Ожидается только иерархия тех корневых задач, у которых есть хотя бы один из выбранных Component/s и выбранная fix version. Корневые типы по-прежнему задаются в настройках иерархии.
4. Найдите Task под выбранным Epic с пустым Component/s или другой fix version. Она должна остаться в дереве: фильтруются корни, а не каждый потомок. Внешние блокеры также доступны независимо от их компонентов.
5. Измените набор компонентов. Старый результат очищается, релиз нужно выбрать заново. Удалите последний компонент — релиз снова недоступен; загрузки всего проекта быть не должно.
6. Перезагрузите вкладку. Компоненты восстанавливаются для текущего сервера/проекта; автоматического запроса задач нет до выбора релиза. Если компонент удалён из справочника, он не восстанавливается. Проверьте другой проект — выбор не должен переноситься.
7. Выгрузите JSON/Markdown или откройте снимок для ИИ: там должны быть ID и названия выбранных компонентов, а также ограниченная ими иерархия.
8. Если выбранные компоненты всё ещё дают более 2000 задач, ожидается ошибка с предложением уменьшить их число. Лимит не увеличен, частичный результат не выдаётся за полный.

Если у корневых задач Component/s не заполнено, они не попадут в выборку даже при наличии этого поля у дочерних задач. Для текущей схемы поле должно быть задано на корневых фичах.
