Наблюдаемая вкладка

Запись выключена.

Пассивная запись не отправляет запросы в Jira и не перехватывает fetch/XHR. После старта перейдите в выбранную вкладку и воспроизведите проблему. Перезагрузка Jira завершает запись в старом документе. Фоновые задержки таймеров не считаются зависанием интерфейса.

Возможные причины замедления

Уверенность показывает силу поддержки конкретного вывода, а не вероятность и не окончательный диагноз. Несколько факторов могут действовать одновременно.

Качество данных и границы выводов

      Рядом с отметкой сбоя

      Окно ±2 секунды вокруг отметки. Совпадение по времени не доказывает причинность; в старых отчётах может не быть точного времени отметки.

      Это проверяемые наблюдения и направления поиска. По браузерным данным нельзя однозначно назначить виновника: медленный TTFB может включать сеть, прокси, очередь приложения и БД.

      Сеть и ответы HTTP

      Короткие активные пробы

      Не ICMP ping: измеряется полный путь HTTP до Jira и обратно. По одному GET, не чаще раза в 2 секунды, тайм-аут 15 секунд, общий бюджет расширения соблюдается. При HTTP-ошибке, странице входа или двух подряд сетевых сбоях серия прекращается. Ожидание бюджета показывается отдельно от измеренного ответа.

      Разбивка по фазам сети

      Нулевые DNS/TCP могут означать кэш или уже открытое соединение; пустое значение — измерение не раскрыто браузером. TCP показан отдельно от TLS. «До отправки» включает подключение и ожидание браузера; это не точная длина очереди сокетов. Protocol — HTTP-протокол, не версия TLS.

      Медленные группы запросов вкладки

      Временная шкала: до 30 самых долгих запросов

      Синий — до отправки; оранжевый — ожидание первого байта; зелёный — получение тела. Числа относятся к странице Jira, включая доступные браузеру запросы её скриптов и расширений.

      Сервер, прокси и downstream

      TTFB — наблюдаемое ожидание первого байта после отправки запроса. Это не чистое время обработки Jira. Server-Timing содержит только метрики, которые сервер или прокси действительно отдали в HTTP-заголовке; их значения могут перекрываться.

      Server-Timing

      HTTP-ошибки и идентификаторы для поиска в логах

      Request ID и node ID показаны только при наличии X-AREQUESTID / X-ANODEID. Отсутствие этих заголовков не является ошибкой. Дата ответа — часы сервера/прокси с ограниченной точностью.

      Чего браузер не видит

      CPU и память сервера, heap JVM, GC, потоки Tomcat, пул и запросы БД, индексация, состояние узлов кластера, диски и внутренние очереди требуют серверных логов или мониторинга. По обычной сессии Jira эти значения не выдумываются. Для администраторов отчёт содержит временной интервал и наблюдаемые симптомы.

      Интерфейс и главный поток

      Загрузка документа

      Долгие задачи и отметки сбоя

      Long task — занятие главного потока на 50 мс и дольше, не процент CPU. Метрика задержки таймера собирается только в видимой вкладке. JS heap — необязательная неточная оценка Chromium, может охватывать общий процесс и не включает всю память вкладки. Значения недоступного API остаются пустыми.

      Тексты Console, stack traces, DOM, заголовки авторизации и содержимое ответов не собираются. Считаются только необработанные JS-ошибки, Promise rejections и ошибки загрузки ресурсов. Для точного стека используйте DevTools в отмеченный момент.

      Нагрузка Board Plus

      Это отдельные счётчики расширения с начала сессии браузера, а не число TCP-сокетов и не весь трафик Jira. HTTP-пробы проходят через этот же бюджет. Пассивные записи не создают HTTP-запросов. Настроить общий бюджет запросов.

      Для сравнения влияния расширения сохраните отчёт, отключите нужные визуальные функции в настройках, повторите тот же сценарий и сохраните второй отчёт. Различие двух запусков само по себе не доказывает причинность.

      Отчёт для инженеров

      JSON содержит обезличенные группы маршрутов, тайминги и счётчики. Параметры URL, ключи задач, названия вкладок, тела запросов/ответов и cookies не включаются. Снимки сохраняются локально только по кнопке, до пяти отчётов для текущей Jira.

      Методика и ограничения API

      HTTP-пробы не измеряют ICMP RTT или потери пакетов. Network Information API даёт общую оценку соединения браузера, а не маршрут к корпоративной Jira. Cross-origin ресурсы могут скрывать фазы без Timing-Allow-Origin. Статус 0 означает «неизвестен», а не успешный ответ. Буфер ресурсов ограничен, начало загрузки до включения записи может быть неполным. Тайм-ауты не отличают DNS, TLS, VPN и прокси.
