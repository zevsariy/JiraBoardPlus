# Ручная проверка Jira Board Plus 0.6.0

Целевая среда: Chrome, Jira 9.17.5#9170005, Timepiece 5.1.2.815, jira.example.com.

Номера A01–P06 совпадают с предыдущим списком. Проверки можно выполнять по разделам. Для каждого пункта отмечайте: **ОК / Не работает / Частично / Не проверено**, а рядом пишите наблюдение. Галочка означает, что проверка пройдена, а не просто выполнена.

## Перед началом

1. Обновите файлы расширения в той же папке, из которой оно установлено. На chrome://extensions нажмите кнопку перезагрузки расширения. Перезагрузите вкладки Jira и ранее открытые страницы расширения. Не удаляйте расширение ради обновления: это удалит локальные данные.
2. Откройте Jira в том же профиле Chrome, убедитесь, что вход выполнен и нужная доска доступна.
3. В меню расширения после изменения галочек, цветов и чисел всегда нажимайте **Применить**. Закрытие меню само по себе не сохраняет изменения.
4. Для изменений Team, меток и полей используйте задачи, которые можно менять. Запишите исходные значения, чтобы вернуть их после проверки. Большинство остальных пунктов только читают данные.
5. В «Инструменты → Профиль команды» сохраните текущие настройки в файл до тестов импорта. Этот файл не содержит сохранённых результатов и снимков.
6. Если нет нужного примера, например двух активных спринтов или задачи с возвратом из Done, отмечайте «Не проверено». Создавать рабочие спринты специально для теста не нужно.

Полезный набор данных: две задачи с разными Team; задачи Bug, Story и Task; задача без исполнителя; просроченная задача; Flagged; задача с давним Updated; первоначальная и позднее добавленная задача спринта; закрытый спринт; задача с изменением оценки; задача с возвратом в статус; известный перенос между спринтами. Найдите ID доски в параметре `rapidView` адреса Jira. Не путайте его с ID спринта.

**Общие ориентиры визуала.** Отдельные страницы расширения имеют синюю шапку с Board Plus и светлые таблицы/панели. Поле Team встроено компактно в Jira и не получает большую фирменную шапку. Изменения на активной доске — снимок данных, а не секундомер: после изменений задачи используйте «Обновить» над доской; фоновое обновление примерно раз в две минуты. Число карточек относится к отображаемой выборке. При ошибке сохраняйте её текст до повторной попытки.

## A. Установка, меню и настройки

- [ ] **A01 — Версия расширения**
  - Шаги: откройте chrome://extensions; найдите Jira Board Plus; откройте «Подробнее»; проверьте версию и переключатель включения.
  - Ожидаем визуально: название Jira Board Plus, версия **0.6.0**, расширение включено. Нет сообщения об ошибке загрузки manifest. Если есть кнопка «Ошибки», откройте её и запишите сообщения, появившиеся после обновления.

- [ ] **A02 — Меню расширения**
  - Шаги: нажмите значок расширений Chrome, затем Jira Board Plus; прокрутите открывшееся меню до конца.
  - Ожидаем визуально: логотип Board Plus, кнопки JQL-отчёта/инструментов/дашборда, настройки функций и кнопка **Применить**. Текст не перекрывает поля, цветовые настройки и кнопки доступны при прокрутке.

- [ ] **A03 — Открытие отдельных страниц**
  - Шаги: по очереди откройте меню и нажмите «Открыть JQL-отчёт», «Дашборд метрик», «Инструменты».
  - Ожидаем визуально: каждый раз открывается вкладка соответствующего инструмента. У JQL — разделы запросов или пустое начало; у метрик — выбор доски/спринта; у DEMO — три кнопки Refinement, История переносов, Профиль команды. Нет пустой белой страницы.

- [ ] **A04 — Сохранение настроек**
  - Шаги: запишите старые настройки; измените порог дней и одну галочку; нажмите «Применить»; закройте и снова откройте меню; затем перезапустите Chrome и проверьте ещё раз.
  - Ожидаем визуально: после применения появляется подтверждение сохранения; выбранные число и галочка остаются после обоих повторных открытий. Верните исходные настройки либо оставьте тестовые для следующих пунктов.

- [ ] **A05 — Общий выключатель визуала**
  - Условие: предварительно включены Team и хотя бы одна функция активной доски/Sprint Report.
  - Шаги: откройте соответствующие страницы; снимите «Дополнения на страницах Jira»; нажмите «Применить»; вернитесь к страницам Jira.
  - Ожидаем визуально: поле Team расширения, дополнительные метки, подсветка, строка сводки и панель Sprint Report убраны. Родные элементы Jira остаются. Вкладки JQL, метрик и DEMO продолжают открываться; расписание JQL не выключается.

- [ ] **A06 — Возврат сохранённого набора функций**
  - Шаги: после A05 снова включите общий выключатель и примените настройки; проверьте те же страницы.
  - Ожидаем визуально: возвращаются именно ранее включённые функции. Отдельные галочки не сброшены. Поля и панели не дублируются.

## T. Team в правой панели бэклога

Подготовка: включите общий визуал и «Поле Team в Details бэклога», нажмите «Применить». Откройте Scrum Backlog и нажмите на задачу, чтобы открыть правую панель.

- [ ] **T01 — Размещение поля**
  - Шаги: найдите в правой панели блок Details; при необходимости разверните/прокрутите его; закройте и снова откройте задачу.
  - Ожидаем визуально: одна компактная строка **Team:** с названием команды или «Без команды». Нет большого блока настроек над проектом/ключом/заголовком. После повторного открытия строка не удваивается.

- [ ] **T02 — Чтение текущего значения**
  - Шаги: выберите задачу с известной Shared Team; дождитесь окончания «Загрузка…»; откройте эту же задачу отдельной вкладкой и сравните Team.
  - Ожидаем визуально: в Details отображается та же команда. Если вместо названия показан `Team <ID>`, запишите это отдельно — чтение ID и получение имени проверяются раздельно.

- [ ] **T03 — Быстрый поиск команды**
  - Шаги: нажмите значение Team; в поле «Найти команду…» введите начало известного названия; допишите/удалите символы; очистите поиск; попробуйте текст, которого нет в названиях.
  - Ожидаем визуально: появляется компактный редактор с поиском, списком Shared Team, «Сохранить» и «Отмена». Список фильтруется при вводе без отдельной кнопки поиска. Совпадение допускается и внутри названия. Текущая выбранная команда может оставаться в списке даже без совпадения; это нормально. Варианты имеют название и ID.

- [ ] **T04 — Сохранение другой команды**
  - Шаги: запишите исходную Team тестовой задачи; найдите и выберите другую Shared Team; нажмите «Сохранить»; дождитесь завершения; обновите полную карточку и затем бэклог.
  - Ожидаем визуально: во время записи элементы временно недоступны, показано «Сохранение…». После успеха редактор закрывается, в строке новое имя. Оно совпадает с полной карточкой и переживает перезагрузку. После теста при необходимости верните исходную Team.

- [ ] **T05 — Очистка Team**
  - Условие: задача допускает пустую Team.
  - Шаги: откройте редактор, выберите «Без команды», сохраните; обновите полную карточку.
  - Ожидаем визуально: редактор закрывается, значение — «Без команды», в Jira поле пустое. Если поле обязательно и очистка недоступна, это не дефект расширения: отметьте ограничение конфигурации.

- [ ] **T06 — Отмена редактирования**
  - Шаги: откройте редактор, выберите другую команду, нажмите «Отмена»; повторите выбор и нажмите Esc. Не нажимайте «Сохранить».
  - Ожидаем визуально: оба раза редактор закрывается, в строке остаётся исходная Team. После обновления страницы значение также прежнее.

- [ ] **T07 — Быстрое переключение задач**
  - Шаги: выберите задачу A; не дожидаясь загрузки, выберите B, затем C; дождитесь завершения загрузки. Повторите с открытым редактором Team без сохранения.
  - Ожидаем визуально: ключ/заголовок правой панели относятся к C, и её Team соответствует полной карточке C. Нет редактора или значения от A/B, дублирующих строк и зависшего «Сохранение…».

- [ ] **T08 — Недостаточно прав или поле отсутствует на Edit Screen**
  - Условие: есть доступная для чтения задача, где Team нельзя редактировать.
  - Шаги: откройте её в бэклоге; дождитесь загрузки строки Team; попробуйте открыть редактор, если он доступен.
  - Ожидаем визуально: поле недоступно/показана ошибка с объяснением; может появиться кнопка «Обновить». Нет активного сохранения, которое сообщает успех без изменения Jira. Запишите точный текст — он поможет различить права, Edit Screen и API команд.

- [ ] **T09 — Независимое отключение Team**
  - Шаги: оставьте общий визуал включённым; снимите только галочку Team; примените; снова включите её и примените.
  - Ожидаем визуально: строка Team исчезает и возвращается. Родные Details и другие функции расширения продолжают работать.

## D. Сводка перед daily

Подготовка: откройте активный спринт; включите «Сводка перед daily», все четыре подгалочки и строку сводки. Нажмите «Применить», затем «Обновить» над доской. Выберите задачи не в Done. Для сравнения учитывайте фильтр доски.

- [ ] **D01 — Задача без исполнителя**
  - Шаги: найдите незавершённую карточку с пустым Assignee; дождитесь загрузки; сравните с назначенной задачей.
  - Ожидаем визуально: у неназначенной карточки есть компактная метка **Нет исполнителя**; у назначенной такой метки нет.

- [ ] **D02 — Давно не обновлялась**
  - Шаги: найдите задачу с известным давним Updated; поставьте порог меньше её возраста, примените и обновите доску; затем поставьте порог больше возраста.
  - Ожидаем визуально: сначала появляется **Без обновл. …** с длительностью, после увеличения порога исчезает. Возраст считается от Updated, а не от даты перехода в статус. Изменение тестовой задачи само обновляет Updated и может убрать метку.

- [ ] **D03 — Просроченный срок**
  - Шаги: выберите незавершённую задачу с Due Date в прошлом; сравните с задачей без срока или со сроком в будущем; обновите данные расширения.
  - Ожидаем визуально: у первой карточки метка **Просрочено**, у второй её нет. Для однозначного примера используйте дату хотя бы на день раньше сегодняшней.

- [ ] **D04 — Флаг блокировки**
  - Шаги: выберите задачу с установленным Jira Flagged/Impediment; обновите данные; на тестовой задаче снимите флаг и обновите снова.
  - Ожидаем визуально: при установленном флаге появляется метка **Флаг**, после снятия исчезает. Родное обозначение Jira может отображаться рядом — расширение не заменяет его.

- [ ] **D05 — Исключение Done**
  - Шаги: найдите задачу в категории Done, у которой формально есть признаки предупреждения, например нет исполнителя или прошёл Due Date; обновите данные.
  - Ожидаем визуально: меток daily нет. Метка времени или подсветка состава могут оставаться: они относятся к другим функциям. Важна категория статуса Jira, а не только текст «Done» в названии колонки.

- [ ] **D06 — Отдельное отключение меток**
  - Шаги: на карточках с несколькими предупреждениями поочерёдно снимайте «Без обновлений», «Нет исполнителя», «Просрочено», «Флаг блокировки»; каждый раз применяйте.
  - Ожидаем визуально: исчезает только соответствующий вид предупреждений. При возврате галочки метки восстанавливаются; дубли не появляются.

- [ ] **D07 — Строка сводки и ручное обновление**
  - Шаги: найдите строку Board Plus над карточками; нажмите «Обновить»; после загрузки снимите только «Строка сводки над доской» в меню и примените.
  - Ожидаем визуально: строка имеет светлый фон, число карточек/предупреждений, время обновления и кнопку. Во время чтения виден статус загрузки. После отключения строка исчезает, метки карточек остаются. Счётчики относятся к отображаемой выборке, а не ко всем задачам команды.

- [ ] **D08 — Quick filters и смена доски**
  - Шаги: включите quick filter, снимите его, переключитесь на другую доску и вернитесь; нажмите «Обновить» после перестроения карточек.
  - Ожидаем визуально: у каждой карточки только один комплект дополнений. Нет меток от другой задачи/доски. Сводка соответствует новой выборке. Новые карточки до обновления могут кратковременно быть без меток.

## S. Задачи, добавленные после старта

Подготовка: включите «Добавленные после старта», рамку и подпись. Найдите по родному Sprint Report одну первоначальную задачу и одну добавленную после старта. Не определяйте это по дате создания задачи.

- [ ] **S01 — Правильная принадлежность**
  - Шаги: откройте активную доску, найдите две подготовленные карточки, нажмите «Обновить»; сравните с отчётом Jira.
  - Ожидаем визуально: позднее добавленная карточка обведена и имеет **+ После старта**. Первоначальная карточка не имеет этой подсветки. Задачи, уже удалённые из спринта, не должны подсвечиваться как его текущий состав.

- [ ] **S02 — Цвет и толщина рамки**
  - Шаги: оставьте рамку включённой; выберите заметный цвет и толщину 1 px, примените; затем задайте 8 px и другой цвет, примените.
  - Ожидаем визуально: рамка нужных карточек явно меняет цвет и толщину. Она не становится рамкой всей колонки; текст карточки остаётся доступным.

- [ ] **S03 — Заливка**
  - Шаги: включите «Заливка карточки»; выберите светлый отличимый цвет и примените; затем измените цвет ещё раз.
  - Ожидаем визуально: фон позднее добавленных карточек меняется; фон первоначальных карточек остаётся родным. Надписи и элементы карточки читаемы.

- [ ] **S04 — Независимость элементов**
  - Шаги: при включённой функции оставьте только заливку; затем только рамку; затем только подпись. Каждый вариант применяйте.
  - Ожидаем визуально: виден только выбранный элемент. Например, при одной подписи нет ни цветной заливки, ни рамки; текст **+ После старта** остаётся.

- [ ] **S05 — Восстановление исходного оформления**
  - Шаги: включите все элементы оформления; запомните карточку; выключите родительскую функцию «Добавленные после старта» и примените.
  - Ожидаем визуально: рамка, заливка и подпись расширения исчезают. Родной цвет/оформление Jira восстанавливаются. Другие метки, например время, остаются при своих включённых галочках.

- [ ] **S06 — Несколько активных спринтов**
  - Условие: на доске действительно несколько активных спринтов.
  - Шаги: найдите позднее добавленные задачи разных спринтов; обновите доску; наведите курсор на «+ После старта» каждой.
  - Ожидаем визуально: подсветка правильна для каждого спринта; подсказка называет соответствующий спринт/спринты. Нет автоматической подсветки всех карточек второго спринта.

## TP. Timepiece и возраст текущего статуса

Подготовка: включите «Время в статусе» и popup; выберите Timepiece, календарь normalHours; примените и обновите доску. Для сравнения в Timepiece используйте ту же задачу, тот же календарь и режим последнего визита.

- [ ] **TP01 — Компактная метка времени**
  - Шаги: дождитесь загрузки активной доски; найдите карточку с известными данными Timepiece.
  - Ожидаем визуально: небольшая метка с иконкой часов и числом часов. Нет большого дополнительного блока. Ошибка вместо числа фиксируется отдельно; бесконечное ожидание также считается проблемой.

- [ ] **TP02 — Совпадение длительности**
  - Шаги: откройте Timepiece для той же задачи; выберите Last visit и normalHours; сравните текущий статус и длительность с меткой расширения после «Обновить».
  - Ожидаем визуально: значения совпадают с учётом округления и времени между запросами. Часы не преобразуются в условные рабочие дни. Большая разница требует записи статуса, календаря и обоих чисел.

- [ ] **TP03 — Открытие popup**
  - Шаги: наведите курсор на часы; уберите курсор; нажмите метку; отдельно попробуйте перейти к ней клавишей Tab.
  - Ожидаем визуально: рядом появляется белое окно с заголовком **Timepiece · KEY**, календарём и временем данных, таблицей статусов и длительностей. Текущий статус выделен цветом/жирным. Нажатие часов не должно перетаскивать карточку.

- [ ] **TP04 — Последний визит вместо суммы**
  - Условие: задача была в одном статусе минимум дважды.
  - Шаги: в Timepiece сравните Last visit и суммарное время этого статуса; откройте popup расширения и найдите строку статуса.
  - Ожидаем визуально: строка соответствует **последнему визиту**, а не сумме. Для не посещённых/недоступных значений допустимо «—», но не выдуманное число.

- [ ] **TP05 — Переключение календаря**
  - Шаги: запишите значение normalHours; смените календарь на 0 или ID используемого рабочего календаря; примените, обновите; выставьте такой же календарь в Timepiece.
  - Ожидаем визуально: popup указывает выбранный календарь, длительности соответствуют ему. Если в интервале есть нерабочее время, число обычно отличается от 24×7. Если различий в интервале нет, одинаковые числа не являются ошибкой.

- [ ] **TP06 — Закрытие и положение popup**
  - Шаги: откройте popup у карточки близко к правому/нижнему краю; прокрутите длинную таблицу статусов, если есть; нажмите Esc.
  - Ожидаем визуально: окно помещается в экран, не обрезается колонкой/карточкой, длинное содержимое прокручивается. Esc закрывает окно, основная доска остаётся на месте.

- [ ] **TP07 — Отключение только popup**
  - Шаги: оставьте время включённым, снимите «Popup по статусам», примените; наведите курсор и нажмите метку.
  - Ожидаем визуально: число с часами остаётся. Большое окно с таблицей не открывается. Обычная текстовая подсказка браузера допустима.

- [ ] **TP08 — Источник Jira**
  - Шаги: переключите источник на Jira; примените и обновите; найдите время последнего входа в текущий статус в истории задачи.
  - Ожидаем визуально: метка показывает календарную длительность от этого перехода до загрузки, подсказка указывает Jira и 24×7. Это не Timepiece; таблица Timepiece не должна выдаваться за данные Jira. При обрезанной истории время неизвестно.

- [ ] **TP09 — Недоступные данные**
  - Условие: встретилась задача с ошибкой Timepiece/доступа либо можно временно отключить сеть после первой загрузки.
  - Шаги: обновите доску в условиях ошибки; наведите курсор на метку неизвестного времени; включите обратно сеть и повторите обновление.
  - Ожидаем визуально: **Время: ?** и объяснение при наведении/в сводке, а не 0 часов. После восстановления доступа число возвращается. Если нет такого случая, отметьте «Не проверено».

## J. JQL-отчёты, расписание и уведомления

Подготовка: откройте JQL-отчёт из меню. Для проверки изменений удобно выбрать 2–3 тестовые задачи и уникальную временную метку, например `jbp_manual_test`. Задайте запрос по вашему проекту и этой метке. Одну задачу включите заранее, другую добавляйте/исключайте изменением метки. Сам JQL между J07–J10 не меняйте. Если нельзя менять задачи, используйте естественные изменения выдачи и отметьте это. После теста уберите временную метку. Системные уведомления Chrome должны быть разрешены в Windows, режим «Не беспокоить» выключен.

- [ ] **J01 — Пустое начало**
  - Условие: в расширении ещё нет запросов. Не удаляйте рабочие запросы только ради этой проверки.
  - Шаги: откройте JQL-отчёт.
  - Ожидаем визуально: фирменная шапка и приглашение добавить первый запрос. Нет демонстрационных разделов, чужих JQL и автоматически загруженных задач. Если запросы уже существуют, пункт можно пропустить.

- [ ] **J02 — Создание и ручной запуск**
  - Шаги: нажмите «Добавить запрос»; задайте название, рабочий JQL, колонки; для начала выключите расписание; сохраните; в новом разделе нажмите «Запустить»; сравните с тем же JQL в Jira.
  - Ожидаем визуально: диалог закрывается, появляется раздел с названием. Сначала показано отсутствие результатов/ожидание, затем таблица, общее количество и дата результата. Набор ключей совпадает с поиском Jira; сохранение само по себе не запускает запрос.

- [ ] **J03 — Несколько запросов в одном отчёте**
  - Шаги: добавьте второй небольшой запрос с другим названием; нажмите «Запустить все»; дождитесь завершения обоих.
  - Ожидаем визуально: два отдельных раздела, каждый со своей таблицей, названием и временем. Навигация отчёта содержит оба раздела. Результаты и счётчики одного запроса не появляются в другом.

- [ ] **J04 — Состав и порядок колонок**
  - Шаги: у тестового запроса нажмите «Настроить»; загрузите список полей; добавьте поле по ID, например известное customfield; удалите одну колонку и переместите другую стрелкой; сохраните и запустите.
  - Ожидаем визуально: сообщение о числе доступных полей; выбранные колонки представлены управляемым списком. После запуска заголовки таблицы идут в выбранном порядке; удалённой колонки нет. Ключ задачи остаётся всегда. Team может возвращаться числовым ID — запишите это, если ожидали имя.

- [ ] **J05 — Кликабельный ключ**
  - Шаги: нажмите ключ любой строки; сравните открывшийся ключ/заголовок с исходной строкой; вернитесь в отчёт.
  - Ожидаем визуально: открыта новая вкладка правильной задачи jira.example.com. Исходная таблица остаётся открытой, ссылка не ведёт на поиск или другую задачу.

- [ ] **J06 — Валидная пустая выдача**
  - Шаги: создайте отдельный тестовый запрос, корректный для Jira, но не находящий задач; запустите.
  - Ожидаем визуально: общее количество 0 и сообщение об отсутствии задач/пустая таблица. Нет красной ошибки HTTP/JQL и бесконечного индикатора загрузки.

- [ ] **J07 — Тихая база сравнения**
  - Шаги: на новом запросе выберите уведомления «О новых задачах в выдаче»; выполните первый успешный запуск.
  - Ожидаем визуально: плашка **База сравнения создана** и полная таблица. Системное уведомление обо всех первоначальных задачах не появляется. Повторный запуск без изменений показывает нулевые изменения.

- [ ] **J08 — Новая задача в выдаче**
  - Шаги: после J07 добавьте временную метку второй тестовой задаче, чтобы она попала в неизменённый JQL; запустите запрос; дождитесь результата.
  - Ожидаем визуально: счётчик **Новых: 1**, новая строка с отметкой **Новая** и цветным акцентом. При разрешённых уведомлениях появляется уведомление с названием запроса и числом новых задач. Не должно быть уведомления о всех старых строках.

- [ ] **J09 — Выход задачи из выдачи**
  - Шаги: установите режим уведомления о появлении и исчезновении; сохраните; уберите временную метку у одной входящей задачи; запустите неизменённый JQL.
  - Ожидаем визуально: задача исчезает из основной таблицы, счётчик вышедших увеличивается, ключ виден в отдельном списке вышедших. При включённых уведомлениях приходит соответствующее сообщение. Это не означает удаление задачи из Jira.

- [ ] **J10 — Изменение выбранного поля**
  - Шаги: выберите «Также об изменениях колонок»; убедитесь, что нужное поле уже есть в колонках и база создана; измените на тестовой задаче это поле, не выводя её из JQL; запустите запрос.
  - Ожидаем визуально: счётчик изменённых увеличивается, строка имеет отметку **Изменена**, в ячейке новое значение. При разрешённых уведомлениях приходит сообщение. Изменение поля вне выбранных колонок может не считаться изменением отчёта.

- [ ] **J11 — Режим без уведомлений**
  - Шаги: выберите «Не уведомлять»; сохраните; измените состав тестовой выдачи; запустите.
  - Ожидаем визуально: таблица и счётчики изменений обновлены, системного уведомления от этого запроса нет. Другие активные запросы могут уведомлять независимо.

- [ ] **J12 — Переход из системного уведомления**
  - Шаги: получите уведомление по J08/J09/J10; нажмите на его тело.
  - Ожидаем визуально: открывается/становится доступна страница JQL-отчёта с соответствующим разделом. Название раздела совпадает с уведомлением. Если уведомление вообще не пришло, сначала зафиксируйте это в J08–J10.

- [ ] **J13 — Автоматический интервал**
  - Шаги: у небольшого тестового запроса поставьте 1–2 минуты и включите расписание; сохраните; запишите время; оставьте Chrome запущенным и компьютер бодрствующим; дождитесь как минимум двух обновлений.
  - Ожидаем визуально: время последнего результата меняется без «Запустить». Первый автоматический запуск ожидается после заданного интервала, а не сразу при сохранении. Допустима задержка планировщика; если обновления долго нет, укажите фактическое ожидание.

- [ ] **J14 — Пауза расписания**
  - Шаги: дождитесь завершения текущего запуска; выключите расписание и сохраните; подождите более одного прежнего интервала с запасом; затем нажмите «Запустить» вручную.
  - Ожидаем визуально: на паузе время результата само не меняется; ручной запуск обновляет таблицу и время. Уже начатый запуск оценивайте отдельно, не принимайте его завершение за новый запуск по расписанию.

- [ ] **J15 — Фон без открытой Jira**
  - Шаги: включите расписание, убедитесь в успешном запуске; закройте вкладки Jira, оставив Chrome и вкладку отчёта; дождитесь следующего интервала.
  - Ожидаем визуально: результат обновляется при действующей серверной сессии. Если корпоративный SSO не допускает это, в отчёте должна быть ошибка входа/доступа, а не успешная пустая выдача. Запишите поведение: этот пункт проверяет реальную корпоративную совместимость.

- [ ] **J16 — Сбой сети после успешного результата**
  - Шаги: на запросе с готовой таблицей запишите количество и время; временно отключите сеть/VPN; запустите; дождитесь ошибки; восстановите связь и повторите запуск. JQL и колонки не меняйте.
  - Ожидаем визуально: видна ошибка запуска, последняя успешная таблица остаётся и не заменяется пустотой. После восстановления связи появляется новый успешный результат. Если нет возможности прерывать сеть, пропустите.

- [ ] **J17 — Неверный JQL**
  - Шаги: создайте отдельный тестовый запрос с синтаксической ошибкой в JQL; сохраните, если форма позволяет; запустите.
  - Ожидаем визуально: сообщение с ошибкой Jira/HTTP 400 и подсказкой проверить JQL. Нет сообщения об успешных 0 задачах. Для этого теста не редактируйте запрос, чью предыдущую таблицу хотите сохранить: смена JQL сбрасывает базу.

- [ ] **J18 — Новая база после изменения конфигурации**
  - Шаги: у тестового запроса с результатами измените JQL, сохраните и запустите; затем отдельно измените набор колонок, сохраните и снова запустите.
  - Ожидаем визуально: после каждого такого изменения первый успешный результат имеет **База сравнения создана**. Нет ложного списка «все задачи новые» относительно старой конфигурации.

- [ ] **J19 — Удаление тестового запроса**
  - Шаги: завершите проверки тестового раздела; нажмите «Удалить»; сначала отмените подтверждение, затем повторите и подтвердите; обновите страницу.
  - Ожидаем визуально: при отмене раздел остаётся. После подтверждения исчезает из отчёта и навигации, после перезагрузки не возвращается. Он больше не создаёт запусков/уведомлений.

## R. Дополнения родного Sprint Report

Подготовка: в меню включите общий визуал, «Инструменты Sprint Report» и все три подгалочки. Откройте классический Sprint Report через раздел отчётов Scrum-доски. Для большинства проверок используйте небольшой закрытый спринт с известным составом.

- [ ] **R01 — Встраивание в отчёт Jira**
  - Шаги: откройте Sprint Report, дождитесь родного отчёта; найдите шапку и область под ней; перезагрузите страницу.
  - Ожидаем визуально: в шапке есть кнопка **Выгрузить для ИИ**, под шапкой светлая панель **Sprint Report · Board Plus** с загрузкой/экспортом/снимками. До загрузки таблицы расширения нет. Панель одна и не закрывает родной отчёт.

- [ ] **R02 — Загрузка выбранного спринта**
  - Шаги: нажмите «Загрузить / обновить данные»; дождитесь сообщения о завершении; сравните имя спринта в панели с выбранным в Jira. Повторите на активном спринте, если доступен.
  - Ожидаем визуально: на время загрузки кнопка недоступна и виден статус. Затем появляются название, состояние, источник оценок/единицы, время данных, фильтры, показатели и таблица. Для закрытого спринта обозначен конец, для активного — текущий срез.

- [ ] **R03 — Категории и состав**
  - Шаги: сопоставьте несколько ключей из каждой доступной категории родного отчёта с таблицей расширения; проверьте отметки «После старта».
  - Ожидаем визуально: задачи имеют правильные категории завершённых/незавершённых/удалённых и отметку позднего добавления. При сравнении количества учтите, что подзадачи по умолчанию исключены и могли быть включены фильтры.

- [ ] **R04 — Фильтр исполнителей**
  - Шаги: в списке исполнителей выберите одного; затем с Ctrl выберите второго; нажмите «Все исполнители». Отдельно попробуйте «Без исполнителя», если он есть.
  - Ожидаем визуально: после выбора остаются задачи выбранных текущих исполнителей, меняются число строк и метрики. При сбросе возвращается вся выборка. Для закрытого спринта это назначение на момент загрузки, а не восстановленный исполнитель на конец спринта.

- [ ] **R05 — Группировка по исполнителю**
  - Шаги: сбросьте фильтр либо выберите двух исполнителей; включите «Группировать по исполнителю», затем выключите.
  - Ожидаем визуально: появляются отдельные подзаголовки с именами и количеством задач, под каждым своя таблица. После выключения снова одна общая таблица. Задачи не пропадают и не дублируются.

- [ ] **R06 — Воздействие на родные таблицы**
  - Шаги: посмотрите родную таблицу Jira ниже панели; выберите исполнителя в расширении; затем сбросьте выбор.
  - Ожидаем визуально: лишние строки родных таблиц скрываются, после сброса возвращаются. Родные графики и их итоговые значения не пересчитываются — ожидаемо; фильтр и новые метрики находятся в панели расширения.

- [ ] **R07 — Быстрая выгрузка JSON из шапки**
  - Шаги: откройте Sprint Report заново, чтобы данных ещё не было; нажмите кнопку «Выгрузить для ИИ» именно в шапке Jira; дождитесь загрузки и скачивания; откройте JSON текстовым редактором.
  - Ожидаем визуально: Chrome показывает скачанный файл `sprint-<ID>-<время>.json`. В панели загружаются данные. В файле правильные board/sprint, массив issues, estimation с единицами, метрики и ссылки. Никакой сайт ИИ автоматически не открывается.

- [ ] **R08 — Markdown и CSV**
  - Шаги: после загрузки выберите Markdown и нажмите экспорт в панели; повторите с CSV; откройте файлы текстовым редактором, Markdown-просмотрщиком или импортом CSV в таблицу.
  - Ожидаем визуально: Markdown содержит таблицу и ссылки, CSV — заголовки и строки, колонку типа и единицы. Кириллица читается. Если Excel открывает CSV одной колонкой, попробуйте импорт с разделителем «запятая» — это отдельно от правильности содержимого файла.

- [ ] **R09 — Весь спринт против фильтрованной выгрузки**
  - Шаги: выберите одного исполнителя/тип; выгрузите JSON с «Весь спринт по паспорту»; затем с «С учётом всех фильтров»; сравните ключи и filters.
  - Ожидаем визуально: первый файл содержит всю выборку по правилу подзадач, второй только отфильтрованную. Метрики каждого файла относятся к его задачам. В JSON фильтрованного файла записаны выбранные типы/исполнители.

- [ ] **R10 — Опциональные описания и история**
  - Шаги: выберите JSON; выгрузите без двух галочек; включите «Описание» и «История», выгрузите снова; сравните одну доступную задачу.
  - Ожидаем визуально: в первом JSON этих свойств у задач нет, во втором есть description/changelog. Отсутствующая история может быть null. На открытом сохранённом снимке полная история и описания не появятся: они в снимок не сохранялись. Markdown/CSV не получают полный текст истории от этих галочек.

- [ ] **R11 — Отдельные выключатели панели**
  - Шаги: при открытом отчёте по одному отключайте экспорт, assignee, карточки метрик; применяйте настройки; затем выключите родительские «Инструменты Sprint Report».
  - Ожидаем визуально: исчезают соответствующие кнопки/управление экспортом, выбор исполнителей или карточки показателей и управление типами. Базовая таблица панели может оставаться. Родительский выключатель убирает всю панель и кнопку шапки, восстанавливает скрытые строки родной таблицы. Повторное включение может требовать загрузить данные снова.

- [ ] **R12 — Смена спринта внутри Jira**
  - Шаги: загрузите расширение для спринта A; средствами Jira выберите B; загрузите данные новой панели; вернитесь к A.
  - Ожидаем визуально: одна панель и одна кнопка экспорта; после смены выбран правильный спринт. Старые таблицы и фильтры A не выдаются за B. Скачанный файл соответствует спринту, указанному в панели.

## M. Дашборд и точность метрик

Подготовка: откройте «Дашборд метрик» из меню. Настройки паспорта редактируются в раскрывающемся блоке панели; после сохранения паспорта нажмите загрузку/обновление данных. Для численной сверки выберите небольшой спринт с полной историей и известными оценками.

- [ ] **M01 — Выбор доски и спринта**
  - Шаги: введите числовой ID доски, context path обычно оставьте пустым; нажмите «Загрузить спринты»; выберите спринт и «Открыть»; затем загрузите его данные в панели.
  - Ожидаем визуально: в списке реальные спринты этой доски с состоянием. Ниже открывается панель, после загрузки — название спринта, показатели и таблица. Ввод ID спринта вместо ID доски не должен приводить к молчаливой выдаче произвольных данных.

- [ ] **M02 — Story Points**
  - Шаги: раскройте паспорт, выберите Story Points; при необходимости укажите действующий ID поля; сохраните и обновите; сравните текущую оценку известной задачи с Jira.
  - Ожидаем визуально: рядом с оценками обозначено **SP**, текущее значение совпадает. Число 5 SP не превращается в часы. Если поле не удалось определить, показана просьба указать его, а не расчёт по другому полю.

- [ ] **M03 — Original Time Estimate**
  - Шаги: выберите этот источник, сохраните и обновите; найдите задачу с исходной оценкой 2 часа или другим точно известным значением.
  - Ожидаем визуально: указан Original Time Estimate и единица **h**; 7200 секунд представлены как 2, а не 7200. Remaining Estimate и Time Spent не используются вместо исходной оценки. Не ориентируйтесь на условный день без знания настроек Jira — пример с часами однозначнее.

- [ ] **M04 — Источник из настройки доски**
  - Шаги: узнайте, какой estimation field задан у этой доски; в паспорте выберите «Из настройки доски», сохраните и обновите.
  - Ожидаем визуально: определён ожидаемый источник SP/Original Time Estimate. Если поле нестандартное или не распознано, появляется понятное требование ручного выбора. Неверный молчаливый источник — ошибка.

- [ ] **M05 — Отдельные паспорта досок**
  - Условие: доступны две доски.
  - Шаги: для доски A сохраните SP, для B — Original Time Estimate; закройте/откройте дашборд; по очереди откройте панели обеих досок и паспорта.
  - Ожидаем визуально: A помнит SP, B — часы; настройки статусов и подзадач также принадлежат своему ID доски. Новая загрузка соответствует этому источнику.

- [ ] **M06 — Оценки на разных датах**
  - Шаги: найдите задачу с изменениями оценки; выпишите её оценку на дату старта, завершения спринта и сейчас из истории Jira; сопоставьте три колонки расширения.
  - Ожидаем визуально: «Старт», «Конец/сейчас» и «Текущая» содержат соответствующие значения и могут различаться. У задачи, созданной после старта, стартовая оценка неизвестна. Если история обрезана, «—» допустимо и должно быть отмечено в качестве данных.

- [ ] **M07 — Неполные данные не равны нулю**
  - Шаги: найдите первоначальную задачу без стартовой оценки или с недоступной полной историей; загрузите выборку, включающую её; откройте определения/качество данных.
  - Ожидаем визуально: неизвестные значения обозначены «—», неполная сумма — числом с `+ ?` и количеством пропусков. Выполнение плана не показано как точный процент при недостающей необходимой оценке. Реальная нулевая оценка и отсутствие оценки различаются.

- [ ] **M08 — Ручная сверка выполнения плана**
  - Шаги: сбросьте фильтры; выпишите первоначальные задачи и их оценки на старте, включая позже удалённые; сложите оценки завершённых первоначальных задач и разделите на сумму первоначального плана. Позднее добавленные исключите из обеих частей.
  - Ожидаем визуально: процент совпадает с ручным расчётом. Пример: первоначально 5 + 3 SP, завершена только задача 5 SP → 62,5%; завершение ещё одной поздней задачи не повышает этот процент. Счётчик всех завершённых при этом может расти.

- [ ] **M09 — Учёт подзадач**
  - Шаги: откройте спринт с подзадачами; при выключенном учёте запишите состав/суммы; включите «Учитывать подзадачи», сохраните и обновите; затем верните выключенное состояние.
  - Ожидаем визуально: сначала подзадач нет в расчёте/таблице, затем они включены. Оценки родителей не заменяются автоматически суммой подзадач: при включении возможен двойной учёт, если команда оценивает оба уровня.

- [ ] **M10 — Фильтр типов задач**
  - Шаги: выберите Bug; сравните строки; затем Story; затем с Ctrl Bug и Task; нажмите «Все типы».
  - Ожидаем визуально: таблица, показатели и число выбранных задач обновляются под каждый набор. В колонке типа только выбранные типы. После сброса возвращается весь состав по остальным фильтрам. Тип — текущий на момент загрузки.

- [ ] **M11 — Отдельные показатели каждого типа**
  - Шаги: включите «Метрики по каждому типу»; выберите несколько типов и, при желании, одного исполнителя; затем снимите галочку.
  - Ожидаем визуально: появляется отдельная сводная таблица со строками Bug/Task/Story и показателями количества, плана, выполнения и медианы cycle time. Значения относятся к текущему фильтру исполнителя. При выключении исчезает только эта таблица, основные метрики остаются.

- [ ] **M12 — Временные метрики**
  - Шаги: на завершённой задаче определите первый вход в рабочий статус и последний вход в Done до конца спринта; посчитайте календарные часы; на незавершённой определите начало текущего на дату среза статуса; сравните возраст/метрики.
  - Ожидаем визуально: cycle time соответствует интервалу первого рабочего входа → последнего Done; медиана/P85 сопровождаются доступным числом задач. Для одной задачи медиана равна её времени. Возраст закрытого спринта считается на конец спринта, активного — на загрузку. Часы 24×7, выходные не вычтены; это не Timepiece. P85 — ближайший ранг.

- [ ] **M13 — Переопределение рабочих и конечных статусов**
  - Шаги: в паспорте укажите числовые ID рабочих статусов через запятую и отдельно конечных; сохраните, обновите; проверьте выбранную задачу по её истории. Затем при необходимости верните пустые значения для выбора из колонок.
  - Ожидаем визуально: в пояснении указаны нужные ID, временные метрики пересчитаны. Нечисловой ID вызывает ошибку валидации. При одинаковых рабочих/конечных статусах данные времени не должны выглядеть достоверным расчётом. По умолчанию работа — средние колонки, Done — последняя.

- [ ] **M14 — Выходы из Done**
  - Шаги: найдите задачу с известным выходом из одного из настроенных конечных статусов во время спринта; проверьте историю и число таких переходов; по возможности сузьте выборку типом/исполнителем.
  - Ожидаем визуально: счётчик **Выходы из Done** включает эти переходы и показывает покрытие историей. Это число переходов, не число уникальных задач; два возврата одной задачи дают два события. Переход Done → другой настроенный Done не считается выходом.

## SN. Снимки спринтов

Подготовка: загрузите данные спринта в дашборде или панели Sprint Report. Снимок сохраняет полный набор задач, без полной истории и описаний; фильтры при открытии снимка сбрасываются.

- [ ] **SN01 — Сохранить и открыть заново**
  - Шаги: нажмите «Сохранить снимок»; запишите спринт/время; перезагрузите страницу и откройте панель той же доски; нажмите «Показать снимки», выберите сохранённый и «Открыть снимок».
  - Ожидаем визуально: после сохранения подтверждение; в списке имя спринта и время. Открываются прежние строки/показатели и сообщение об открытии сохранённого снимка. Отсутствие описаний/полной истории в снимке явно обозначено. Открытие снимка не требует заново получать все задачи Jira.

- [ ] **SN02 — Сравнение счётчиков**
  - Шаги: выберите старый снимок; загрузите более свежие данные либо другой спринт с той же конфигурацией оценок; нажмите «Сравнить со снимком».
  - Ожидаем визуально: блок сравнения называет оба спринта и показывает «было → стало» с разницей для завершённых, добавленных, незавершённых и удалённых. При сравнении идентичных данных разница нулевая. Полного сравнения текстов всех полей здесь нет.

- [ ] **SN03 — Фильтры при сравнении**
  - Шаги: выберите тип Bug и одного исполнителя, нажмите сравнение; измените тип на Story; снова нажмите сравнение.
  - Ожидаем визуально: каждый расчёт относится к одинаковым выбранным фильтрам обеих выборок. Сразу после смены фильтра старый блок сравнения очищается; новый появляется после повторного нажатия. Если подходящих задач в снимке нет, его счётчики могут быть нулевыми.

- [ ] **SN04 — Запрет смешивания единиц/правил**
  - Шаги: сохраните тестовый снимок в SP; переключите паспорт на часы, сохраните и обновите; выберите SP-снимок и нажмите сравнение. Отдельно попробуйте различие галочки подзадач.
  - Ожидаем визуально: сообщение, что нельзя сравнить разные поля/единицы оценок или правила подзадач. Не появляется численная разница, выдаваемая за корректную. После теста верните паспорт доски.

- [ ] **SN05 — Удаление снимка**
  - Шаги: выберите ненужный тестовый снимок; нажмите «Удалить снимок»; отмените подтверждение и проверьте наличие; затем повторите с подтверждением и обновите список.
  - Ожидаем визуально: после отмены снимок остаётся; после подтверждения исчезает. Остальные снимки этой доски и других досок доступны. Удаление снимка не меняет Jira.

## F. Подготовка к refinement

Подготовка: откройте «Инструменты → Refinement». Начальная строка `*` включает оценку, описание и Team. Строка конкретного типа полностью заменяет общую, а не дополняет её. Имена типов вводите как в Jira. Для применения к результатам после редактирования нажимайте **Проверить**; «Сохранить правила» сохраняет набор для следующих открытий. Само изменение галочек старый результат не пересчитывает.

- [ ] **F01 — Проверка по JQL**
  - Шаги: выберите источник JQL; вставьте небольшой корректный запрос по известным задачам; включите хотя бы одно правило; нажмите «Проверить»; сравните ключи с поиском Jira, сняв «Только проблемы…».
  - Ожидаем визуально: сообщение о загрузке сменяется завершением; над таблицей источник/время, общее число, сколько проверено и сколько проблем/неизвестных полей. Таблица содержит ключ, название, тип, проблемы и то, что не удалось проверить. Изначально JQL не предзаполнен.

- [ ] **F02 — Проверка backlog доски**
  - Шаги: выберите «Backlog доски»; в появившееся поле введите ID; нажмите «Проверить»; сравните с задачами вне активных/будущих спринтов этой доски.
  - Ожидаем визуально: поле JQL скрыто, показано поле ID. В результате источник «Backlog доски <ID>». Задачи запланированных будущих спринтов могут отсутствовать — это ожидаемая семантика API; для них используйте JQL.

- [ ] **F03 — Каждая проверка заполненности**
  - Шаги: подготовьте примеры без оценки, без описания, без Team, без Epic Link, без исполнителя; в применимой строке типа поочерёдно включайте соответствующую галочку и запускайте проверку.
  - Ожидаем визуально: в колонке «Проблемы» указан конкретный отсутствующий атрибут; у заполненной задачи такого сообщения нет. Если поле не получено/недоступно, сообщение находится в «Не удалось проверить», а не выдаётся за отсутствие значения. Для Epic/подзадач включайте проверку Epic Link только если она нужна по вашим правилам.

- [ ] **F04 — Особые правила для Bug**
  - Шаги: включите проверку оценки у `*`; добавьте строку с именем Bug как в Jira; у неё выключите оценку, но включите, например, описание; проверьте Bug без оценки и Story без оценки.
  - Ожидаем визуально: Bug не получает проблему «Нет оценки», Story получает её по правилу `*`. Bug проверяется только по своей строке. Если у строки Bug выключены все проверки, при просмотре всех задач он отмечается как не проверявшийся.

- [ ] **F05 — Отключение правила**
  - Шаги: на задаче с известной проблемой выполните проверку; снимите соответствующую галочку в применимой строке; нажмите «Проверить» повторно.
  - Ожидаем визуально: эта проблема исчезает из нового результата, остальные остаются. Если выключены вообще все проверки во всех строках, запуск сообщает, что нужно включить хотя бы одну; пустой отчёт не обозначается как успешная проверка всего.

- [ ] **F06 — Ноль и неизвестные поля**
  - Шаги: проверьте задачу с оценкой 0, другую с пустой оценкой; если есть, добавьте задачу с недоступным для чтения полем.
  - Ожидаем визуально: у нулевой оценки нет «Нет оценки», у пустой есть. Недоступное поле перечислено отдельно как непроверенное. Счётчик неизвестных полей/задач помогает отличить отсутствие данных от качества backlog.

- [ ] **F07 — Источник оценки и независимость остальных правил**
  - Шаги: на подходящих задачах выполните проверку с SP, затем с Original Time Estimate; сравните наличие оценок соответствующих полей. Затем выключите проверку оценки во всех строках, оставьте описание и проверьте без заполненного ID SP.
  - Ожидаем визуально: итоговая строка называет выбранный источник/единицы. Результат меняется в соответствии с заполненностью именно выбранного поля. При полностью выключенной оценке другие правила работают без определения SP; указан текст, что оценки не проверяются.

- [ ] **F08 — Показать только проблемы / все задачи**
  - Шаги: после загрузки включите «Только проблемы и неизвестные поля», затем снимите; откройте ключ задачи с проблемой.
  - Ожидаем визуально: с галочкой остаются только проблемные/непроверенные поля; без неё также видны корректные задачи и задачи без правил. При отсутствии проблем показано, что в этой выборке нет задач, а общая статистика остаётся. Ссылка ведёт на правильную задачу.

- [ ] **F09 — Сохранение правил и отмена чтения**
  - Шаги: измените набор типов/галочек, нажмите «Сохранить правила», закройте и откройте DEMO; затем запустите достаточно долгую проверку и нажмите «Отменить» до её завершения.
  - Ожидаем визуально: после открытия восстановлены сохранённые типы, галочки и источник оценки. При отмене появляется сообщение об отмене, кнопка запуска снова доступна, частичная таблица не представляется полным успешным результатом. Если маленькая выборка загрузилась раньше нажатия, повторите на другой или отметьте, что отмену не удалось проверить.

## H. История переносов

Подготовка: «Инструменты → История переносов», ID доски. Обычный запуск читает Sprint Report, подробности дополнительно читают историю повторяющихся задач. В расчёте только последние выбранные 2–30 активных/закрытых спринтов по дате старта; это не вся жизнь задачи и не вся компания.

- [ ] **H01 — Выбор периода**
  - Шаги: введите доску и 3 последних спринта, нажмите «Показать историю»; запишите покрытие; повторите с 10 или другим доступным числом.
  - Ожидаем визуально: во время работы сообщения о загрузке очередного спринта; после — «Проверено N из M», диапазон дат старта и время данных. При расширении периода могут добавиться задачи/участия. Если спринтов всего меньше запроса, указано фактическое количество.

- [ ] **H02 — Известная незавершённая задача следующего спринта**
  - Шаги: найдите задачу, которая была незавершённой в закрытом спринте A и присутствовала в более позднем B, начавшемся не раньше завершения A; включите их в период; найдите строку задачи.
  - Ожидаем визуально: колонка переносов содержит как минимум это событие, число участий не меньше двух; в истории перечислены A и B с правильными датами и категориями. Один такой переход даёт 1 перенос, а не 2. Это наблюдение по отчётам, не доказательство прямого перемещения A → B.

- [ ] **H03 — Повторные участия без переноса**
  - Шаги: снимите «Только задачи с переносами»; найдите задачу с несколькими участиями, которая не удовлетворяет условию переноса; снова включите галочку.
  - Ожидаем визуально: без галочки видны все найденные повторные участия, в том числе с 0 переносов. С галочкой нулевые строки исчезают. Задачи, участвовавшие только один раз, эта таблица не показывает в обоих режимах.

- [ ] **H04 — Пересечения и удаления**
  - Условие: есть известный случай пересекающихся спринтов или задача, удалённая из одного из них.
  - Шаги: сравните даты спринтов и категории задачи в родных Sprint Report; найдите её в истории с отключённым фильтром только переносов.
  - Ожидаем визуально: само повторное присутствие в пересекающихся спринтах не засчитано как перенос. Следующее участие только в категории удалённых также не образует перенос из предыдущего незавершённого. В истории при этом видна категория «Удалены из спринта».

- [ ] **H05 — Подробности: оценки и возраст**
  - Шаги: проверьте паспорт этой доски в дашборде метрик; вернитесь в историю, включите дополнение оценками/возрастом и запустите; найдите задачу с полной историей и изменением оценки.
  - Ожидаем визуально: после чтения отчётов идёт прогресс чтения задач. Добавляются колонки оценок «старт → конец» для каждого участия с единицами SP/h и текущего статуса/возраста. Возраст здесь текущий на загрузку, не на конец старого спринта. Часы календарные 24×7; оценки совпадают с историей или показаны «—» при невозможности восстановления.

- [ ] **H06 — Ошибки, неполнота и отмена**
  - Шаги: во время достаточно долгой загрузки нажмите «Отменить»; отдельно, если встретится недоступная задача при включённых подробностях, осмотрите её строку. При естественной ошибке Sprint Report запишите статус.
  - Ожидаем визуально: отмена показана явно и не публикует частичный итог как полный. Ошибка одного отчёта останавливает общий результат. Ошибка подробностей отдельной задачи видна в её строке; уже вычисленные участия остаются, неизвестная оценка не становится 0. После отмены можно запустить повторно.

## P. Экспорт и импорт профиля команды

Подготовка: сначала выгрузите собственный профиль и сохраните отдельно. Импорт меняет локальные настройки: это реальная операция, а не просмотр. Для теста нового JQL удобно передать профиль между отдельными тестовыми установками либо использовать отдельную копию JSON с одним явно названным тестовым запросом. Домен профиля должен оставаться jira.example.com. Не меняйте рабочие настройки наугад ради проверки.

- [ ] **P01 — Содержимое экспорта**
  - Шаги: «Инструменты → Профиль команды → Выгрузить настройки JSON»; откройте скачанный файл редактором; найдите queries, visual, refinement, profiles.
  - Ожидаем визуально: Chrome скачивает `jira-board-plus-team-profile.json`; структура имеет схему team-profile/v1, домен Jira, JQL с колонками/интервалами, визуальные настройки, правила и паспорта по ID. Нет результатов задач, снимков и данных сессии. Запросы в переносимом профиле подготовлены к импорту на паузе.

- [ ] **P02 — Просмотр без записи**
  - Шаги: выберите валидный файл профиля через поле импорта; прочитайте блок просмотра; не нажимайте применение; откройте меню расширения и проверьте текущие настройки.
  - Ожидаем визуально: перечислено число JQL, число правил типов, ID досок, context path, предупреждение о замене визуала и тексты JQL. Кнопка применения доступна. До её нажатия настройки не меняются. Просмотр не показывает все значения настроек; при необходимости сравните сам JSON.

- [ ] **P03 — Применение просмотренного профиля**
  - Шаги: используйте профиль с известным отличием, например цветом рамки и правилом Bug; нажмите «Применить просмотренный профиль»; откройте заново меню и Refinement; для проверки доски включите соответствующую функцию.
  - Ожидаем визуально: подтверждение успешного импорта; цвет/правила соответствуют файлу, открытая доска получает настройки визуала. Паспорта обновлены только для указанных в профиле досок. Сами задачи Jira не редактируются.

- [ ] **P04 — Новые запросы на паузе, без дублей**
  - Шаги: импортируйте профиль с одним отсутствующим тестовым запросом; откройте JQL-отчёт и его настройки; повторно импортируйте тот же файл.
  - Ожидаем визуально: после первого импорта новый раздел существует, расписание выключено, автоматического результата/уведомления нет. После второго точного импорта нового дубля нет, число добавленных — 0. Имеющийся аналогичный запрос с другой конфигурацией колонок/интервала может быть отдельной записью — это не точный дубликат.

- [ ] **P05 — Сохранность имеющихся данных**
  - Шаги: до импорта запишите время/число строк существующего JQL-результата и имя одного снимка; примените профиль; откройте тот же раздел и список снимков этой доски.
  - Ожидаем визуально: прежние результаты и снимки на месте, импорт не заменил их задачами из файла. Профиль может изменить паспорт расчёта будущих загрузок, но сохранённый снимок остаётся со своими данными. Новые результаты появляются только от последующих запусков.

- [ ] **P06 — Отклонение неверного файла**
  - Шаги: создайте отдельный маленький файл с некорректным JSON и выберите его; затем на копии валидного файла измените origin на другой домен и попробуйте выбрать; при наличии подходящего случая проверьте конфликт context path с существующими запросами.
  - Ожидаем визуально: показана ошибка формата/домена, кнопка применения недоступна, старый просмотр не остаётся доступным для случайного применения. Конфликт context path отклоняется при применении без частичной записи. Текущие настройки и данные сохранены. Оригинальный экспорт не изменяйте.

## Как присылать результат

Достаточно перечислить проблемные номера; пройденные можно объединять диапазонами. Пример:

```
Версия расширения: 0.6.0
Chrome: <версия>
Проверено: A01–A06 ОК, T01–T02 ОК
Не проверено: S06 — один активный спринт

Пункт: TP03
Статус: Не работает / Частично
Страница: активный спринт / backlog / Sprint Report / вкладка расширения
Настройки: Timepiece, календарь 0, Popup включён, нажал Применить
Шаги: навёл курсор на часы у карточки, затем нажал
Ожидал: окно со статусами
Увидел: <что именно появилось или не появилось>
Точный текст ошибки: <если есть>
Повторяется: все задачи / один тип / одна задача / иногда
После обновления страницы: то же самое / заработало
Скриншот: <при необходимости>
```

Если отображение отсутствует, на скриншоте полезно показать место, где оно ожидалось, и настройки функции. Для неверного числа нужны два значения: расширение и Jira/Timepiece, выбранный календарь/источник и время сравнения.

Если есть ошибка запроса: откройте DevTools (F12) на проблемной вкладке → Network → повторите действие → найдите неуспешный Fetch/XHR. Пришлите HTTP-код, путь endpoint без чувствительных параметров и короткий обезличенный текст ошибки. Для фоновых JQL-запросов Network вкладки может быть пуст: сначала пришлите ошибку в самом отчёте; при необходимости отдельно разберём service worker расширения. Cookies, Authorization, полный HAR и необезличенные большие ответы не нужны.

## Завершение тестирования

Верните исходные Team, тестовые метки и поля задач, если меняли их. Удалите ненужные тестовые запросы либо выключите их расписание. Верните желаемые визуальные настройки/паспорта; при необходимости используйте собственный экспорт профиля. Помните: импорт профиля не восстанавливает удалённые результаты/снимки и не включает расписание новых импортированных запросов автоматически.
