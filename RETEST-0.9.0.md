# Личные заметки — ручная проверка

1. Обновите расширение и перезагрузите вкладки Jira. В настройках → Дополнения на досках включите «Личные заметки к задачам», сохраните. Галочка по умолчанию выключена.
2. На активной Scrum/канбан-доске нажмите кнопку «Личные заметки» на карточке. Откроется модальное окно с ключом задачи, списком записей и редактором. Добавьте текст. Должны появиться запись и время создания; в Jira обычный комментарий не появляется.
3. Откройте ту же задачу в бэклоге, затем в правой панели Details, затем по ссылке /browse/KEY. Везде кнопка открывает те же записи. У другой задачи список отдельный.
4. Нажмите «Редактировать», измените текст и сохраните. Проверьте обновлённую запись из другого режима. Введите Dev — горячие клавиши Jira не открывают окно редактирования issue. Enter внутри редактора добавляет новую строку; сохранение — кнопкой.
5. Откройте одну запись на редактирование в двух вкладках. Сохраните первую, затем вторую. Вторая должна показать конфликт и сохранить набранный текст в редакторе, не затерев первую. Обновление списка доступно по кнопке.
6. Удалите запись: сначала должно появиться подтверждение. «Отмена» оставляет запись. После подтверждения она исчезает и в других режимах после обновления списка.
7. Закройте окно с несохранённым текстом через крестик/Escape — требуется подтверждение. Перезагрузите вкладку: сохранённые записи остаются.
8. Выключите функцию, затем включите: кнопки исчезают и возвращаются, сохранённые записи остаются. Общий выключатель визуала тоже скрывает заметки. Открытый несохранённый редактор при выключении закрывается.
9. Экспорт профиля команды и Sprint Report не должен содержать тексты личных заметок. При другом адресе Jira одинаковый ключ задачи имеет отдельные записи.

Записи не синхронизируются между устройствами/профилями. Доступ к одному профилю браузера означает доступ к его заметкам, даже после смены аккаунта Jira. Не используйте как единственное хранилище важных данных: удаление расширения очищает его локальное хранилище.
