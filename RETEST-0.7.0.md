# Повторная проверка исправлений · Jira Board Plus 0.7.0

Обновите файлы в той же папке расширения, перезагрузите расширение в chrome://extensions, затем вкладки Jira. Убедитесь, что версия 0.7.0. Настройки меню сохраняйте через «Применить». Проверки ниже заменяют соответствующие пункты MANUAL-QA-0.6.0.md; остальные его разделы остаются актуальными.

## Team — T01, T03, T04–T06

- [ ] **T01. Три места.** Включите «Поле Team в Details досок». Откройте задачу справа последовательно в Scrum Backlog, активном спринте и Kanban. В каждом доступном режиме в Details должна быть одна компактная строка Team с правильным значением.
- [ ] **T03. Один ввод.** Кликните значение Team и начните печатать название. Фокус уже находится в поле, текущий текст выделен для замены. Под тем же полем открыт фильтруемый список, отдельного select и кнопки сохранения нет. Введите несуществующее название — показано «Команды не найдены», Enter не должен ничего записать.
- [ ] **T04. Enter и клик.** На тестовой задаче введите часть названия, выберите стрелками и нажмите Enter. После завершения редактор закрывается, видна новая Team. Повторите выбор другой команды кликом мышью. Сверьте оба изменения в полной карточке. На одну операцию не должно быть двойного сохранения.
- [ ] **T05. Очистка.** Для необязательного поля выберите «Без команды» в списке (можно набрать этот текст). Очистка сохраняется сразу после выбора. Для обязательной Team такой вариант не предлагается.
- [ ] **T06. Отмена.** Откройте поле, введите поиск, нажмите Esc. Затем повторите с кликом вне редактора. Значение не меняется. Быстро переключите задачу при открытом редакторе: список старой задачи закрывается.

## Стабильность доски и исполнитель — D01

- [ ] **D01-a. Выбор карточки.** Включите daily и время, дождитесь загрузки. Нажмите карточку A, затем B, закройте Details. Метки других карточек не исчезают, загрузка всех задач заново из-за самого выбора не начинается. Проверяйте вскоре после загрузки: плановое обновление примерно раз в 2 минуты сохраняется.
- [ ] **D01-b. Медленное обновление.** Нажмите «Обновить» над доской. В сводке виден статус обновления, прежние метки остаются до нового результата. При ошибке рядом появляется предупреждение; старые данные не выдаются за свежие без предупреждения.
- [ ] **D01-c. Перерисовка Jira.** Примените quick filter, снимите его, дождитесь штатного обновления Jira или сверните/разверните Details. Для уже загруженных карточек метки восстанавливаются из кеша без ожидания всех сетевых ответов. Новая, ранее не загруженная карточка может потребовать чтения.
- [ ] **D01-d. Нет исполнителя.** Найдите незавершённую неназначенную задачу; включите daily и «Нет исполнителя», примените и обновите. Метка должна появиться. Если она не появилась, пришлите статус задачи и список завершённых статусов из меню: такие задачи исключаются из daily.

## Зависимости вместо Flagged — D04, D05

Включите daily и «Блокировки по связям». Нужна карточка со статусом Blocked (любой регистр) и ссылками is blocked by. Проверка не меняет статусы задач.

- [ ] **D04-a. Один открытый блокер.** У карточки одна блокирующая задача в незавершённом статусе. Ожидается красная ЗАБЛОКИРОВАНА; по наведению/клику видны ключ блокера и статус.
- [ ] **D04-b. Несколько блокеров.** Один завершён, второй открыт. Карточка всё ещё ЗАБЛОКИРОВАНА. Завершите второго только если это разрешённая тестовая задача либо найдите готовый пример; после обновления при всех завершённых ожидается зелёная РАЗБЛОКИРОВАНА. Сама карточка остаётся в Blocked — это сигнал DEMO, не автоматический переход.
- [ ] **D04-c. Направление.** Задача, которую текущая карточка сама блокирует (`blocks`), и связь `relates to` не влияют на метку. У карточки не в статусе Blocked новая метка не показывается. Если нет is blocked by, метки также нет.
- [ ] **D04-d. Неизвестный блокер.** Если блокирующая задача недоступна и все остальные известные блокеры завершены, ожидается БЛОКИРОВКА: ?, а не зелёная метка. Если есть известный открытый блокер, остаётся красная; в popup видны ошибки остальных.
- [ ] **D05. Завершённые статусы.** В меню задано `Done, Closed, Resolved, Obsolete`. Проверьте, что карточка с таким именем статуса не получает обычные предупреждения daily, а блокер с таким статусом считается завершённым независимо от регистра. Добавьте свой конечный статус и повторите после применения/обновления. Если нужно опираться только на список имён, выключите «Также учитывать категорию Done в Jira». Это настройка daily/блокеров, а не паспорта метрик Sprint Report.

## Popup «После старта» — S06

- [ ] **S06. Наведение, клик, клавиатура.** Найдите карточку с меткой + После старта. Наведите курсор, затем проверьте клик и фокус через Tab. Должно открываться отдельное белое окно с именем спринта/спринтов и источником. Esc закрывает. Нажатие метки не должно открывать другую карточку или начинать перетаскивание. Проверьте возле края доски: popup не обрезается колонкой.

## Время — TP01, TP02, TP03

- [ ] **TP01-a. Единицы.** Источник Timepiece, режим текущего визита. Переключите часы → дни → недели, применяя настройку. Единицы должны совпадать на карточке и во всех строках popup. Пример: 168 ч = 7 д = 1 нед. Значения округляются до двух знаков, маленькое значение может округлиться к 0; для точной проверки выберите часы.
- [ ] **TP01-b. Календарь.** Сравнивайте с Timepiece на том же календаре. Перевод в дни всегда делит полученные часы на 24, в недели — на 168; это не число восьмичасовых рабочих дней. Изменение календаря может изменить исходные часы; изменение только единиц не меняет саму длительность.
- [ ] **TP02-a. Текущий визит.** На задаче с возвратом в текущий статус выберите «Текущий визит в статус». Сравните с Last visit Timepiece. На карточке — текущий визит; у прочих статусов в popup — последний визит.
- [ ] **TP02-b. Сумма визитов.** Переключите на «Сумма всех визитов в статус», примените, дождитесь обновления. Сравните с Total Timepiece для той же задачи/календаря. Время текущего статуса и строки popup учитывают все визиты. Например, два визита 24 и 48 часов → 72 ч / 3 д. Единицы самопроизвольно не меняются при смене режима.
- [ ] **TP03-a. Popup.** Наведите на часы или нажмите метку. Белое окно содержит ключ задачи, источник, режим, календарь, время данных и статусы. Текущий выделен; неизвестные значения обозначены —. Окно не должно исчезать просто из-за обхода DOM расширением.
- [ ] **TP03-b. Отключение popup.** Снимите только «Popup по статусам», примените. Время остаётся, таблица по наведению/клику больше не открывается. Верните галочку — таблица снова доступна.
- [ ] **TP03-c. Источник Jira.** Переключите источник на Jira. При полной истории оба режима и выбранные единицы работают так же; календарь 24×7. При неполной истории показано неизвестное время и объяснение. Данные Jira не обозначаются как Timepiece.

Результаты удобно прислать так: `D01-a ОК; D04-b не работает — два блокера, Closed и Open, видна зелёная метка; TP03-a popup не открывается`. Для неверного времени укажите источник, режим, единицы, календарь, статус и оба сравниваемых числа. Для проблем с Team — режим доски (Backlog / Scrum / Kanban) и место, где поле ожидалось. Не присылайте cookies, Authorization и полный HAR.
