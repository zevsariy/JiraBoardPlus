# Refinement: выбор проверок · 0.7.8

1. После обновления откройте инструменты. В шапке должна быть версия 0.7.8. Выберите доску и выборку. Поля JQL, Context path и вариант «Свой JQL» в Refinement отсутствуют.
2. В блоке «Какие проблемы проверять» видны десять правил. Выключите все общей галочкой, включите только «Нет описания», нажмите «Проверить». В результатах должны учитываться только отсутствие/недоступность описания, с учётом исключений по типам. Общая галочка находится в промежуточном состоянии.
3. Нажмите «Выбрать все правила». Все десять галочек включены. Запустите проверку: учитываются выбранные проверки, кроме явно отключённых для конкретного типа. Повторный клик снимает все галочки. При попытке проверки без правил появляется просьба включить хотя бы одно.
4. Отдельно проверьте новые поля: приоритет, компонент, целевая версия, метки и срок выполнения. Пустой массив компонентов/версий/меток — проблема. Если поле не вернулось из Jira, оно показано в «Не удалось проверить», а не как подтверждённо пустое.
5. Раскройте исключения по типам. Добавьте, например, Bug и выберите только описание для этого типа. При включённых общих оценке и описании Bugs проверяются только на описание; остальные типы — на оба поля. Отключение общей галочки описания выключает эту проверку также для Bug.
6. Нажмите «Сохранить правила», перезагрузите страницу: набор и исключения восстановлены. В списке «Показывать» переключите проблемы на все задачи выборки — это меняет только представление результата, без нового запроса. Изменение самих галочек очищает старый результат и требует новой проверки.
7. Проверьте те же правила для спринта, Scrum-бэклога и Kanban-колонки. Выборка должна оставаться в пределах выбранной доски; ручного JQL не требуется. Ссылки задач открывают вашу Jira.
